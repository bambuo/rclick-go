## 1. 范围与前置

只调整设置窗口的布局与文案层级。保留六个分区、现有字段、草稿与脏状态、保存校验、原子写入和 Finder 扩展刷新。前置条件：本机 macOS 与 Xcode 命令行工具可执行 `make dev`。

## 2. 目标布局

- 窗口标题栏保持现有 `RClick Settings`。
- 主体改为左右两栏：左侧固定分区导航，右侧为标题、说明、分组表单与底部操作区。
- 左侧六项：通用、应用、操作、新建文件、文件夹、命令，顺序与现有 `settingsState.tab` 的 0–5 对应。
- 右侧顶部显示当前分区标题与一句说明；表单使用单列分组和轻分隔线，不新增卡片嵌套。
- 内容底部固定为状态文本、还原与保存操作；脏状态下保存与还原可用。
- 窗口默认 880×720、最小 700×560；默认尺寸已在真实窗口中确认。

分区内容保持现状：

| 分区 | 现有内容 |
| --- | --- |
| 通用 | Finder 菜单开关、默认值、Open With 全局参数与环境、语言、登录启动、Dock |
| 应用 | 打开方式应用列表、每个应用的参数与环境、继承开关、移除与添加 |
| 操作 | 五个 Finder 文件操作的启用开关与重置 |
| 新建文件 | 六种默认文件类型的启用、名称、扩展名、移除、重置与添加 |
| 文件夹 | 常用文件夹、监视的文件夹、添加与移除 |
| 命令 | 快捷命令的启用、名称、危险确认、模板、移除、重置与添加 |

## 3. 组件与函数契约

保留 `settingsState` 的 `draft`、`dirty`、`status`、应用参数与环境缓存，以及现有各分区绘制函数。原 `tab int` 改为 `section string`，由侧栏直接维护当前分区 ID。分区元信息为纯数据：

```go
type settingsSection struct {
    ID       string
    LabelKey string
    DescKey  string
}

func settingsSections() []settingsSection
func currentSettingsSection(id string) settingsSection
func (a *App) settingsView(c *ui.Context)
```

- `settingsView` 使用 `ui.Row` 与 `ui.Sidebar` 构建左右栏，不再使用 `ui.Segmented`。
- 侧栏六项使用 24×24 单色 SVG 图标：设置、应用、操作、新建文件、文件夹、命令；图标随选中态着色。
- `settingsSections` 返回六个分区，顺序固定为 general、apps、actions、newfiles、folders、commands。
- `currentSettingsSection` 对未知 ID 回退到 general，避免空选中。
- 右侧内容继续调用 `generalTab`、`appsTab`、`actionsTab`、`newFilesTab`、`foldersTab`、`commandsTab`。
- 底部状态、还原与保存直接写在 `settingsView` 内，复用 `saveSettings`、`revertSettings` 与 `a.settings.dirty`。
- 新增 i18n 文案：`Settings sections`、`Unsaved changes` 与六个分区说明；保存、还原、已保存、已恢复沿用现有文案。
- 不改 `internal/config/types.go`、`validate.go`、`atomic.go`、`internal/ipc`、`native/`。

## 4. 交互与状态

| 场景 | 行为 |
| --- | --- |
| 切换分区 | 保留当前草稿与脏状态，只切换右侧内容 |
| 编辑任意字段 | `dirty` 置真，保存与还原可用，状态显示未保存 |
| 保存成功 | 沿用现有校验、原子写入、语言应用、托盘重建与 `running` 通知；状态显示已保存 |
| 保存失败 | 显示现有保存失败状态，草稿与脏状态保留，不写入文件 |
| 还原 | 从 `store.Current()` 重新填充草稿，`dirty` 置假，状态显示已恢复 |
| 添加应用或文件夹 | 保留现有原生选择器；原型中的自绘弹窗不进入实现 |
| 添加文件类型或命令 | 沿用现有输入、校验与状态提示 |

## 5. 链路与生效点

1. 用户从托盘打开设置窗口，`showSettings` 决定是否刷新草稿。
2. 分区导航只改变 `tab` 与右侧内容，不改配置。
3. 用户保存后进入现有保存链路：校验、原子写入、更新草稿、应用语言、重建托盘、发送 `running`。
4. Finder 扩展收到状态通知后重新读取共享配置并刷新菜单。

## 7. 边界

- 无新增 HTTP、gRPC、消息队列或后台任务。
- 无配置 JSON 键变更，无数据库变更。
- 不改变 Finder 菜单结构、通知名、helper 命令或快捷命令执行方式。
- 不把原型中的模拟弹窗、模拟保存或演示文案带入应用。
- 本需求无对外接口变更；前端对接文档只记录设置界面交接信息。

## 8. 观测点

- 保存失败时沿用 `Save failed: ...` 状态文本；成功时为 `Saved`。
- 还原后状态为 `Reverted to the saved configuration`。
- 保存成功必须触发一次 `running` 通知。
- 分区切换、脏状态和按钮禁用状态在右侧底部可见。
